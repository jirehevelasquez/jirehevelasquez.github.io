Indoor UAV Localization and Payload Pickup was a team-based ME 423 robotics project focused on building and testing a small quadrotor UAV system for GPS-denied indoor localization, MAVLink-based flight-controller communication, Kinect-based visual feedback, and payload interaction using a suspended electromagnet end effector.

Overview

The goal of this project was to demonstrate a small UAV system that could operate in an indoor, GPS-denied environment using an offboard depth camera for position feedback. Instead of relying on GPS, the system used an Xbox 360 Kinect camera to detect and localize a target object in three-dimensional space. The measured position was then transformed into a coordinate frame useful for the drone and communicated to the flight controller through MAVLink.

The larger mission concept was to have the drone localize itself, navigate toward a ferromagnetic package, activate an electromagnet end effector, transport the payload, and release it at a selected drop-off location. The final project did not fully complete the entire pickup/drop-off mission, but it successfully demonstrated several major subsystems: UAV assembly, flight-controller communication, camera-based object tracking, frame transformations, EKF-origin setup, MAVLink data transmission, and closed-loop hover testing.

Problem / Goal

Indoor UAV autonomy is difficult because GPS is unavailable or unreliable. The engineering problem was to create an alternate localization pipeline that could estimate drone or target position using vision data, transform that measurement into a useful navigation frame, and pass the result to the drone's flight-control stack.

The project also introduced a mechanical payload interaction challenge. The drone needed enough thrust, structural stiffness, and packaging space to support avionics, a battery, radio hardware, and a suspended magnetic end effector while still remaining flyable and controllable.

My Role

My role focused on controls and software integration. I worked on the software and communication side of the drone, including MAVLink communication, flight-controller setup, localization data handling, testing scripts, and mission-state logic for the planned pickup/drop-off sequence.

  • Helped develop Python scripts for communicating with the Cube Orange flight controller through PyMAVLink.
  • Worked on setting the EKF/global origin and verifying MAVLink communication with the flight computer.
  • Supported Kinect-based localization using OpenCV, OpenNI2, HSV masking, centroid detection, and depth measurements.
  • Worked with coordinate transformations from camera measurements into North-East-Down style coordinates.
  • Helped test and debug closed-loop position feedback during early hover testing.
  • Developed mission-state logic for a planned pickup/drop-off sequence using search, approach, attach, drop-off, release, and done states.

Engineering Process

The project began with a search-and-rescue inspired UAV concept. The team first defined the major subsystems: airframe, propulsion, flight controller, battery, receiver, external sensing, onboard communication, and end effector. Early design work used a standard quadrotor architecture because it provided a practical balance between maneuverability, component availability, and control complexity.

As the project matured, the design shifted toward a more specific indoor-localization and payload pickup demonstration. The final design included larger propellers, larger motors, a redesigned 3D-printed frame, a Cube Orange flight controller, an ELRS radio link, an offboard Kinect sensing system, and a suspended electromagnet end effector. This changed the project from a broad rescue-drone concept into a more focused robotics proof-of-concept.

Technical Work

UAV Hardware and Mechanical Integration

  • Used a quadrotor configuration to provide six-degree-of-freedom motion with four propellers.
  • Integrated propulsion hardware, ESC stack, flight controller, receiver, battery, wiring, and payload hardware.
  • Evaluated packaging constraints for the electronics stack, battery, propeller clearance, and suspended payload.
  • Iterated from the original frame concept toward a refined 3D-printed design with updated motor and propeller sizing.
  • Integrated an electromagnet end effector below the airframe for planned package pickup and release.

Computer Vision and Depth Sensing

  • Used an Xbox 360 Kinect as an offboard depth camera for indoor localization.
  • Used OpenNI2 to access color and depth streams from the Kinect.
  • Used OpenCV to convert images into HSV color space and generate masks for target tracking.
  • Detected a colored target by identifying the centroid of masked pixels in the image frame.
  • Used depth measurements near the centroid to estimate the target's distance from the camera.
  • Converted pixel and depth information into 3D Cartesian position measurements relative to the camera frame.

Frame Transformations and Localization

A major part of the project was defining the frames needed to relate the camera, drone, tool, and target package. The team modeled the universal frame, camera/Kinect frame, drone frame, tool or electromagnet frame, and package frame. The localization problem required transforming measured target locations from the Kinect frame into a frame useful for drone motion and payload pickup.

  • Defined coordinate frames for the camera, drone, end effector, and target package.
  • Used transformation matrices to relate camera measurements to drone-relative motion commands.
  • Converted camera-frame position data into North-East-Down style coordinates for MAVLink communication.
  • Used Python and NumPy for matrix operations, coordinate conversions, and testing calculations.

MAVLink, ArduPilot, and Flight-Controller Communication

  • Used PyMAVLink to communicate with the Cube Orange flight controller.
  • Worked with MAVLink messages for heartbeat detection, EKF/global-origin setup, local position feedback, and vision-position estimates.
  • Used ArduPilot and Mission Planner for configuration, calibration, parameter access, and flight-controller setup.
  • Tested communication over both direct USB-C connection and wireless communication pathways.
  • Verified that localization data could be sent to the flight controller as part of the closed-loop feedback workflow.

Mission-State Logic

The mission script was structured around a finite state machine intended to guide the drone through a complete payload mission. The intended sequence was:

  • SEARCH: identify and lock onto the drone and package targets.
  • APPROACH_PACKAGE: move the drone toward the detected package location.
  • ATTACH: activate the electromagnet when the tool is close enough to the package.
  • GO_TO_DROPOFF: move toward a user-defined drop-off direction and distance.
  • RELEASE: deactivate the electromagnet to release the package.
  • DONE: end the mission sequence.

This full mission-state code was written as a planned integration path, but the final project timeline ended before the team could fully combine the hover-test communication code with the complete pickup/drop-off autonomy script.

Tools Used

  • Flight Control: Cube Orange, ArduPilot, Mission Planner, MAVLink, PyMAVLink
  • Computer Vision: Xbox 360 Kinect, OpenNI2, OpenCV, HSV masking, centroid tracking, depth sensing
  • Programming: Python, NumPy, Matplotlib, dataclasses, finite state machine logic

Results / Status

The team successfully demonstrated several key parts of the system. The Kinect-based vision pipeline was able to track a colored target, identify its centroid, and use depth data to estimate its position in three-dimensional space. The system also successfully communicated with the flight controller using MAVLink, and the team was able to configure the EKF/global origin after tuning connection and flight-controller settings.

During hover testing, the closed-loop feedback system showed that camera-derived position data could be sent to the drone as part of the localization workflow. The system was not perfect: turbulence from the indoor test area, lighting sensitivity in the computer-vision mask, and drift from the setpoint created instability and limited position-holding performance. The final pickup/drop-off waypoint mission was not fully integrated before the project deadline, but the project still validated the core sensing, communication, and control architecture needed for future development.

Challenges and Debugging

  • Lighting sensitivity: HSV masking and depth readings were affected by changing room lighting and surrounding objects.
  • Indoor turbulence: flight testing near desks, lockers, and room obstacles caused disturbed airflow and hover instability.
  • MAVLink setup: the team had to tune connection settings and flight-controller parameters to reliably communicate with the Cube Orange.
  • EKF/local-origin limitations: EKF/global-origin setup was achieved, but local-origin setup was more limited and worked best through a direct USB-C connection.
  • System integration timeline: the team produced separate working components, but the full autonomous pickup/drop-off mission was not completely integrated before the final deadline.

Key Takeaways

This project gave me practical experience integrating mechanical hardware, flight electronics, computer vision, state estimation, and Python-based communication into a real UAV system. It also showed the difference between developing working subsystems and integrating them into a reliable full-stack autonomous robot.

The biggest engineering lesson was that UAV autonomy depends heavily on reliable sensing, correct frame transformations, clean communication, and stable flight behavior. Even when the software logic is reasonable, real-world issues like lighting changes, airflow disturbance, estimator setup, and communication reliability can dominate system performance.
